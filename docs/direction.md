# アプリの方向性

このアプリが作るのは、別の世界にいるキャラクターと、音声通話の端末ごしに会話するエージェント。

- キャラクターは自分の世界の自分の部屋にいる。部屋に置いた音声通話の専用端末が、ある日突然ユーザーの端末とつながった。なぜつながったのかは誰も知らない。
- つながった時点で二人は初対面。今どのくらい親しいかは、キャラクターが覚えている会話（記憶）だけで決まる。キャラクターの設定に「ユーザーとの関係」の欄を置かないのはこのため。
- キャラクターはユーザーの世界に行けず、ユーザーの世界のことも（自分の世界に同じものがなければ）知らない。ただし道具は、つながった端末を通してユーザーの PC に実際に作用する。
- 話す相手は現実のユーザーで、会話は今この時点の出来事。してもいないこと、道具が返していないことを事実のように言わせない。
- 二つの世界の時間は同じ速さで進み、話していない間もキャラクターは自分の世界で暮らしている。前回話した時刻（キャラクターの全部の会話で最後の発言）と経過時間を毎回渡し、間が空いたときにその間のことを話させる。どのくらいを「久しぶり」とするかは LLM に任せ、その間の出来事は保存しない（話したことが記憶に残る）。

## 地の文

- 地の文（`*…*` の動作や物音の描写）は書かせない。返答は声に出す言葉だけで、システムプロンプトの応答スタイルでそう指示する。
- 以前の会話に残っている地の文や、LLM が指示に反して書いてしまった地の文のために、`*…*` を読み上げない処理と画面での表示はそのまま残す。

## 通話画面の表情

- 通話画面には、キャラクターの表情画像を「相手の写真」として出す。映像ではないので、プロンプトでは見た目に触れさせない。
- 表情は返答の LLM に選ばせない（タグを書かせない）。読み上げる一文ごとに、ユーザーの発言とそれまでの返答を添えて Decisions API に聞き、キャラクターが画像を持つタグ（好感度で解放済みのもの）と「ふつう」から選ばせる。
- 判定は音声合成と同時に進め、その文の再生と一緒に表情を切り替える。判定できなかった文は前の表情のまま。モデルは「表情の判定」の設定を使い、未設定なら表情は変わらない。

## キャラクターの設定

キャラクターカードは使わず、このアプリ独自の項目を持つ。キャラクターを作ると、すぐに設定の画面が開く。

手持ちの資料（txt / md / json）は「資料から読み取る」で、返答のモデルに読ませて下の項目に書き起こせる。形式をそのまま取り込むのではなく、あくまで独自の項目の下書きを作る（保存はユーザーが選んでから）。

| 項目 | 内容 |
|---|---|
| 名前 / 呼び名 | 呼び名は画面での表示だけに使う |
| 参考画像 | 顔として表示し、表情を AI で作るときの元にする |
| 世界観 | キャラクターが暮らす世界 |
| プロフィール | 年齢・立場・経歴・好きなものなど |
| 見た目 | キャラクターが自分の姿を語るときのため（LLM は参考画像を見ない） |
| 性格 | |
| 喋り方 | 一人称・語尾・口癖・セリフの例など |
| 部屋の様子 | 端末の置き場所と、そこで聞こえる音 |
| 端末 | この世界での端末の呼び名と形 |

- キャラクターはセリフの中で、端末とそれを通して使う道具をこの世界の物として語り、ツール名やキャラクターの世界にない技術の名前は口にしない。端末が空欄なら世界観に合う呼び名と形を LLM が決める。
- 「資料から読み取る」は、資料に端末のことがなければ世界観から考えて下書きする（ほかの項目は資料にあることだけ）。

## プロンプト

- システムプロンプトと応答スタイル（日本語で書く・声の絵文字）はアプリに固定で、設定からは変えない（プリセットもない）。ユーザーが書けるのは、その後ろに追記するカスタムプロンプトだけ。端末という前提とキャラクターの設定はその後ろに付く。
- キャラクターは受け身にしない。おしゃべりの相手として、自分の気持ちや意見を返し、ユーザーに話題を振り、提案をする（覚えていること・時間帯・道具でできること）。ただし質問や提案は1回の返答に1つまでで、詰問しない。
- 今の日時は、会話履歴のあとのシステムメッセージに毎回入れる（履歴より前に置くとプロンプトのキャッシュが効かなくなるため）。
- ask_user（選択肢）は、作業の進め方の確認など、ユーザーに決めてほしいことがあるときだけ使う。

## 好感度

- キャラクターごとに好感度を持ち、`characters/<id>/affinity.json` に保存する。会話の中身は見ず、話し方のルール（話した日、1日の往復はあとになるほど軽く、キャラクターが起こしたイベントに応えた）だけで数える。ワーキングメモリーの変化はコントロールが難しいので数えない。値もレベルも下がらない。
- レベルはポイントに加えて、話した日数と出会ってからの日数がそろったときに上がる。たくさん話しても日を重ねないと深い関係にはならない。
- 会いたさ（0〜100）は好感度とは別に持つ。話していない日ごとにレベルに応じてたまり、1往復ごとに減る。好感度には影響させず（不在の罰にしない）、`[Relationship]` の言葉と「おかえり」「寂しかった」「やきもち」の条件にだけ使う。
- 「通話」の概念はない。声のイベントはユーザーがマイクで話したかで判定する。
- 親しさは記憶で決まるので、記憶を消去すると好感度も最初に戻る。キャラクターのエクスポートには含めない。
- プロンプトには点数ではなくレベルを言葉で渡す（会話の後ろの `[Relationship]`）。レベルごとの接し方はアプリに固定で、ユーザーは書き換えられない。照れ・好きの表情は一定のレベルから使える。
- 作業メモリの「今の関係」「距離感」は `[Relationship]` を超えて書かない。
- イベントはレベルと会話の状況からルールで選び、1日に1つまで。届け方は「開口一番」（新しい会話をキャラクターと始めたとき、キャラクターから話す）、「返事の中で」、「手紙」の3つ。
- 思い出話など過去に触れるイベントは、先に LLM に下書きさせ、実際のメッセージ id か記憶メモを根拠に挙げられないものは捨てる。過去を作り話しない。
- 開口一番の合図はユーザーの隠しメッセージとして保存し、画面と履歴には出さない。開口一番の返事は往復に数えない。
- 恋愛は常に有効で、設定はない。レベル5で告白し、次の返事で受けるか読む（24時間答えがなければ断ったことにする）。恋人から友達に戻すのは画面からだけ。
