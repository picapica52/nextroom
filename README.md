# Nextroom

キャラクターと声で会話するためのローカル GUI です。音声合成には [Irodori-TTS](https://github.com/Aratako/Irodori-TTS) v4.1（Small / Small MF）、文字起こしには speech.cpp のカタログから選んだ日本語のモデルを使い、どちらも別に起動した [speech.cpp](https://github.com/nyosegawa/speech.cpp) のサーバー（`speech serve`）に HTTP で頼みます（Python は不要です）。参照音声（Voice Clone）の声づくりは、キャラクターの声の画面で行えます。

- **会話**: マイクで話しかけると、speech.cpp で文字起こし → pi が対応するプロバイダー（Anthropic・OpenAI・OpenRouter・Google・xAI・GitHub Copilot・Groq・Mistral・DeepSeek など。API キーか、ChatGPT / Claude / GitHub Copilot / SuperGrok などのサブスクのサインインで使う）か、OpenAI 互換 API（Ollama / LM Studio など）の LLM に送信 → 返答を Irodori-TTS で読み上げ。返答は1文ずつ合成して順に再生するので、全文を待たずに話し始めます。会話画面はキャラクターの顔と字幕を中心に、プッシュトゥートークで聞き取ります。マイクのボタン（入力欄の外では Space キー）を押している間だけ録音し、離すと送信します。返答の読み上げ中に押すと読み上げを止めて話せます。文字でも話しかけられます。返答の声（モデル・話速・Voice Clone・キャプション）はキャラクターごとに指定できます。
- **キャラクター**: エージェントの人格になるキャラクターを、このアプリ独自の設定（世界観・プロフィール・見た目・性格・喋り方・部屋の様子・端末）とアイコン・返答の声つきで保存。キャラクターは自分の世界の自分の部屋にいて、そこに置いた音声通話の端末があなたの端末と突然つながった、という前提で話します。返答は声に出す言葉だけです。道具はつながった端末を通して実際にあなたの PC で作業します（方針は [docs/direction.md](docs/direction.md)）。サイドバーの「キャラクターを作る」を押すと、すぐにキャラクターの設定が会話の上に開きます（設定も同じく会話の上に開きます）。新しい会話を始めるときに話し相手を選びます。書き出しは、アイコンや声のファイルも含めたこのアプリ用の zip です。
- **チーフ**: 最初から「チーフ」というキャラクターが1人いて、削除できません。チーフに「こんな人と話したい」と頼むと、会話の中で新しいキャラクターを作ったり、ほかのキャラクターの設定や指示を書き換えたりします（作成と変更は「設定 → 承認」の確認の対象です）。アイコンと声は、できたキャラクターの設定で決めます。
- **エージェント**: キャラクターは [pi](https://github.com/earendil-works/pi)（`@earendil-works/pi-agent-core`）のエージェントとして動き、「設定 → 道具」でオンにした道具を会話の中で使います。返答の下と会話の右パネルに道具の実行ステップが表示されます。確認のしかたは「設定 → 承認」で選び（確認しない / 自動 / 確認）、確認が必要な操作は入力欄の上で「許可 / 常に許可 / 拒否」を聞いてから実行します。
  - **ルーティン**: キャラクターが決まった時間に自分で動きます（「毎朝7時に起こして」と頼むか、キャラクター画面の「ルーティン」で作ります）。結果はキャラクターからのメッセージとして会話に残ります。キャラクター画面の「詳細」では、そのキャラクターだけのモデル・使わない道具・指示を決められます。
  - **メモリー**: 記憶はデータベース（`_data/nextroom.sqlite`）に持ちます。キャラクターが会話の中で自分で書き直すメモ（`MEMORY.md`。書き直すたびに版を残します）、会話の記録（長くなった古い部分は要約し、そのときメモも更新）。キャラクター画面の「記憶」タブでメモと要約を見たり、消したりできます。
  - **コンピューター**: キャラクターごとに、ブラウザとターミナルの入った Linux のコンピューター（Docker のコンテナ）を1台持たせます。コマンドも画面の操作も、この中だけで動きます。設定の「コンピューターを使う」1つでオンになります。この PC のファイルには触れません（[docs/desktop.md](docs/desktop.md)）。
  - **ワークスペース**: コンピューターの `/workspace` で、キャラクターごとの Docker ボリュームにあります。会話の右パネルの「ファイル」で中身を見たり、ファイルを置いたりできます。
  - **コマンド**: キャラクターはコマンド（`execute_command`）でファイルを読み書きしたり、プログラムを動かしたりします。
  - **デスクトップ**: 画像を読めるモデルなら、画面を見ながらクリックや入力でも操作します。その画面は会話の「デスクトップ」で見たり、操作を代わったりできます。
- **声**: キャラクターの「声」タブで、実行先（speech.cpp の Irodori-TTS・ElevenLabs・Fish Audio）とモデルをキャラクターごとに選びます。speech.cpp サーバーが読み込めるモデルは1つなので、違うモデルのキャラクターが話すときは先にモデルを読み込み直します。
  - **参照音声**: Voice Clone で使う音声を、キャラクターのフォルダ `_data/characters/<id>/voice/` にアップロードします（WAV 以外はブラウザで WAV にしてから送ります）。同じ画面でボイスファイル（音声を一覧の順に1つにつないだ WAV、合計120秒まで）を作ります。speech.cpp サーバーはこれを参照音声として受け取ります。音声を追加・削除したら、ボイスファイルを作り直します。手元の .wav や speech.cpp で作った .voice.gguf をそのまま読み込むこともできます。
  - **ElevenLabs**: アカウントの声から選ぶほか、キャラクターの参照音声からの複製（Instant Voice Clone）や、説明文からの作成（Voice Design）もこの画面で行えます。説明文は、会話の LLM がキャラクターの設定から考えることもできます。
  - **Fish Audio**: アカウントの声か、Fish Audio で公開されている声（名前で探すか、声のページのアドレスを貼り付けます）から選びます。キャラクターの参照音声から非公開の声を複製することもできます（書き起こしがあれば一緒に送ります）。API キーは「設定 → 接続」で入力します。
- **設定**: 左上の検索から設定の項目を探せます。一般（名前・すべてのキャラクターへの指示）、接続（AI のプロバイダー・音声・Web のサービスの API キーとサインイン）、モデル（メインモデルとフォールバック）、音声、道具（Web 検索・アプリ連携・コンピューターなど）、承認（確認のしかた・承認モデル）、Discord・Slack（[docs/discord.md](docs/discord.md)・[docs/slack.md](docs/slack.md)）。文字起こしのモデルは「音声」で、音声合成のモデルはキャラクターの声の画面で選ぶと、speech.cpp サーバーがダウンロードして読み込みます。

## 必要なもの

- Windows（x64）・macOS（Apple Silicon）・Linux（x64）。動作確認: Windows + RTX 4070 Ti 12GB
  - speech.cpp のサーバーは自分で起動します（[docs/speech-server.md](docs/speech-server.md)）。[リリース](https://github.com/nyosegawa/speech.cpp/releases)から OS に合った版を取得します
  - Windows: Vulkan 版（GPU のドライバが必要）
  - macOS: Metal 版
  - Linux: Vulkan 版。Vulkan のローダー（`libvulkan.so.1`）がなければ CPU 版
- [Bun](https://bun.sh/) 1.4 以上、Git
- 会話用の LLM（「設定 → 接続」で API キーかサブスクのサインインで設定する pi のプロバイダー、または OpenAI 互換 API）。記憶の道具をいつも使うので、ツール呼び出し（function calling）に対応したモデルが必要です
- 道具を使う場合のみ: コンピューターには Docker Desktop

## セットアップと起動

```powershell
.\setup.ps1           # 初回のみ: 依存パッケージのインストールと画面のビルド
.\start.ps1           # サーバーを起動し、http://127.0.0.1:8767 を開く
.\start.ps1 -Dev      # 画面・サーバーを開発モード（https://127.0.0.1:5175）で起動
```

「このシステムではスクリプトの実行が無効になっているため…」と出て実行できない場合は、PowerShell の実行ポリシーで止められています。次のどちらかで実行してください。

```powershell
# 自分のユーザーだけ、ローカルのスクリプトの実行を常に許可する（管理者権限は不要。一度だけでよい）
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 設定を変えずに、その回だけ許可して実行する
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

macOS と Linux では、スクリプトの代わりに次を実行します。

```sh
bun install && bun run build  # 初回のみ
bun run start                 # サーバーを起動し、http://127.0.0.1:8767 を開く
bun run dev                   # 画面・サーバーを開発モード（https://127.0.0.1:5175）で起動
```

Docker Compose で起動する場合は [docs/docker.md](docs/docker.md) を見てください（`docker compose up -d --build`）。

同じネットワークのスマホからは `https://<PC の IP>:8768`（開発モードでは `https://<PC の IP>:5175`）で開きます。ブラウザは HTTPS のページにしかマイクを使わせないため、サーバーが自己署名の証明書を作って HTTPS でも待ち受けます（`_data/tls`）。初めて開くときに出る「安全ではない」という警告を許可して進んでください。

接続先と API キーは「設定 → 接続」で入力するとデータベースに保存されます。LLM のプロバイダーのキーやサインインは pi のしくみで保存され、入力していないものは pi が読む環境変数（`OPENROUTER_API_KEY`・`ANTHROPIC_API_KEY`・`GEMINI_API_KEY` など）から読みます。それ以外（Exa・Composio・ElevenLabs・Fish Audio・OpenAI 互換 API・speech.cpp）は、入力していないものを `apps/server/.env` から読みます（項目と既定値は `apps/server/.env.schema`）。書き換えたあとはサーバーを起動し直してください。

```sh
# apps/server/.env の例（画面で入力しない場合）
OPENROUTER_API_KEY=sk-or-...
OPENAI_COMPATIBLE_BASE_URL=http://127.0.0.1:11434/v1
```

声で話すには、speech.cpp のサーバーを別に起動しておきます。次のようにモデルを渡さずに起動してから、「設定 → 音声」の文字起こしと、キャラクターの声の画面でモデルを選びます（詳しくは [docs/speech-server.md](docs/speech-server.md)）。接続先の既定は `http://127.0.0.1:8080` で、「設定 → 接続」か `.env` の `SPEECH_URL` で変えられます。

```powershell
speech serve --open
```

## 構成

bun workspaces + Turborepo のモノレポです。`.\start.ps1` は turbo でサーバーを、`-Dev` では画面の開発サーバーも一緒に起動します。

```
apps/
  web/                React + Tailwind CSS v4（Vite）。画面はこれ1つ
    src/app/            エントリ・ルーティング
    src/features/       画面ごとの機能（chat / call / characters / agent / workspaces / settings）
    src/components/     画面をまたぐ部品
    src/hooks/          共通のクエリ（queries.ts）と、GPU ジョブ・再生（engine.ts）
  server/             Hono（Bun）: /api と、ビルド済み画面の配信。環境変数は varlock（.env.schema）
packages/
  api/                サーバー側の中身（apps/server が読み込む）
    src/routes/         /api 以下のルート（Hono。HTTP の入口だけ）
    src/agent/          エージェント（pi）: 会話、道具（tools/: コンピューター・コマンド・デスクトップ・記憶など）、
                        メモリー、LLM の接続とプロバイダーのサインイン、声、実行ステップと確認
    src/conversations/  会話モード（文字起こし → エージェント → 1文ずつ音声合成）
    src/characters/     キャラクター（保存・書き出し、アイコン、プロンプト組み立て）
    src/engine/         エンジン: speech.cpp サーバーのクライアント（音声合成・文字起こし）、
                        GPU ジョブのキュー、speech.cpp サーバーのモデル
    src/settings/       設定（chat: 会話、agent: エージェント）
    src/lib/            データフォルダーのパス・データベース（Drizzle ORM、テーブルは schema.ts）・エラー・ジョブを1つずつ実行するキュー・子プロセス
    drizzle/            データベースのマイグレーション（起動時に適用。schema.ts を変えたら `bun run db:generate`）
  contracts/          画面とサーバーで共有する型と、リクエストを確かめる zod スキーマ
  ui/                 shadcn/ui（Base UI・nova）の部品とテーマ
  config/             共通の tsconfig
docs/                 見た目のルール
_data/                会話・キャラクター・設定（git 管理外）
  nextroom.sqlite       データベース（bun:sqlite + Drizzle ORM）: 設定（chat・agent・discord・slack）、キャラクター（人物設定・声・詳細の設定）、
                        好感度、会話（記録と要約）、メモ（MEMORY.md）とその版、参照音声の一覧、プロバイダーの API キーとサインイン情報。
                        ルーティンとその実行履歴、接続先と API キー（入力したもの）
  characters/<キャラクター>/  キャラクターのファイル
    avatar.png            アイコン
    voice/                参照音声とボイスファイル
    images/               会話の画像（ユーザーが添付したもの）
  uploads/              アップロードの一時ファイル（1日で消える）
  tls/                  HTTPS の自己署名証明書
```

キャラクターの書き出しに入るのは、人物設定・アイコン・声だけです（好感度・会話・記憶・ワークスペースは入りません）。キャラクターを削除すると、ワークスペースも消えます。記憶を消去しても、ワークスペースのファイルは残ります。

画面は Bun のサーバー（8767）だけにアクセスします。エンジンはサーバーの一部で、`/api/engine/*`（speech.cpp サーバーのモデル・GPU ジョブ）で使います。音声合成と文字起こしは、ユーザーが別に起動した speech.cpp サーバーに HTTP（OpenAI 互換の `/v1/audio/speech`・`/v1/audio/transcriptions`）で頼みます。Voice Clone の声は、初めて使うときにサーバーの `/speech/voices` へ送って加えます。

LLM の呼び出しは [pi](https://github.com/earendil-works/pi)（`@earendil-works/pi-ai` と `pi-agent-core`）を通します。プロバイダーは pi が対応するもの（pi の ID で選ぶ）と、アプリが加える OpenAI 互換 API で、それぞれ「設定 → 接続」で pi が用意する方法（API キーかサブスクのサインイン）で設定します。モデルは「設定 → モデル」のメインモデル（キャラクターごとに変えたときはそのモデル）を使い、失敗したときは何か話す前ならフォールバックのモデルを順に試します。キーとサインイン情報はデータベースに保存されます。

会話の1往復はサーバーのキューで1つずつ実行されます。speech.cpp に頼む処理（生成・文字起こし）とボイスファイル作成はエンジンのキューで1つずつ順番に実行されます。返答の途中で止めると、リクエストを切るので合成中の文も speech.cpp 側で止まります。

## エージェントの道具について

- 道具は記憶とルーティン以外、最初はオフです。会話画面の「道具」か、「設定 → 道具」でオンにしてください。
- 「設定 → 承認」のモードで、変更を伴う操作（画面の操作・ファイルの書き込みや削除・コマンド・アプリでの送信など）を確認するかを決めます。「自動」では承認モデルが依頼に合うかを判断し、合わないものや取り消せないものだけ確認します（承認モデルがなければ「確認」と同じ）。「常に許可」にした操作と、ブロックにした操作は一覧で変えられます。確認待ちのあいだ返答は止まり、会話を止める（停止ボタン）と確認は「拒否」になります。ルーティンの実行中は誰も答えられないので、確認が必要な操作はしません。
- コンピューターは、キャラクターごとに1つのコンテナ（コンピューター）を使います。ワークスペースとホームはそのキャラクターの Docker ボリュームにあり、この PC のフォルダはマウントしません。メモリ・CPU・コマンドの制限時間は設定で変えられます。
- サブスクでの利用は、サインインした本人が個人で使うためのものです。各サービスの規約を確認してください。Claude のサブスクは、サードパーティのアプリからの利用がプランの枠ではなく追加の利用料金になることや、使えなくなることがあります。

## 補足

- LoRA と Large は speech.cpp が対応していないため使えません。
- 画面には API キーそのものは返さず、設定済みかどうかだけを返します。マイクの録音はブラウザ内で 16kHz WAV にしてから送るので、FFmpeg は不要です。長い録音は無音で区切ってから文字起こしします。
- 他人の声を複製する場合は、利用規約と本人の許諾を確認してください。各モデルのライセンスは Hugging Face のモデルカードを参照してください。
